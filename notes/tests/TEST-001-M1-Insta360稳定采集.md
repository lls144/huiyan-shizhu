# TEST-001 M1 Insta360 稳定采集

- **Test ID**：TEST-001
- **对应 Requirement ID**：HW-002、HW-003
- **日期**：2026-09-03
- **被测 Git commit**：`d2b864d852e3910ba10a6572c0bd98bb8249a9f0`

## 测试目标

验证 Windows 11 上能按设备名称选择 Insta360 Ace Pro 2，并以配置模式连续采集；同时验证重复打开/关闭能力。仅测试摄像头采集，不测试轮廓识别。

## 环境

- 电脑：主开发电脑
- OS：Microsoft Windows 11 家庭版 中文版，64 位，Build 26200
- Python：3.12.10，仓库 `.venv`
- OpenCV：`opencv-python` 5.0.0.93，`cv2.__version__` 5.0.0
- NumPy：2.5.2
- 设备：Insta360 Ace Pro 2，VID `2E1A`，PID `1003`
- 后端：DirectShow
- 光照/实验条件：室内自然光与室内照明；摄像头本次未使用三脚架垂直俯拍，未铺设 A3 白色背景

## 输入条件

- 配置：`pc/config/camera.json`
- 首选设备名称：`Insta360 Ace Pro 2`
- 请求格式：MJPG，1920×1080，30 fps
- 连续采集时长：60 秒
- 打开/关闭循环：3 次
- 工程验收门槛：成功率 ≥ 99%；最大成功帧间隔 ≤ 2 秒；3 次重新打开均能读取首帧；实际分辨率与请求一致

## 操作步骤

1. 使用 Windows PnP 和 OpenCV/DirectShow 枚举视频设备。
2. 运行 `python -m pytest -q` 验证配置与设备选择逻辑。
3. 运行 CLI 枚举命令，按名称选中 Insta360 Ace Pro 2。
4. 运行 3 秒烟雾测试，确认正式脚本和 1920×1080 模式可工作。
5. 在 commit `d2b864d` 上运行 60 秒正式稳定性测试并保存 JSON 与代表帧。
6. 连续采集结束后释放设备，再执行 3 次“打开 → 读取首帧 → 释放”循环。

## 预期结果

- 按名称选中 Insta360，不依赖固定索引。
- 实际输出 1920×1080 MJPG。
- 60 秒内成功读帧率 ≥ 99%，最大成功帧间隔 ≤ 2 秒。
- 3/3 次重新打开并读取首帧成功。

## 实际结果

- OpenCV/DirectShow 枚举：内置摄像头索引 0、Insta360 Ace Pro 2 索引 1、OBS Virtual Camera 索引 2。
- 实际属性：1920×1080，MJPG，设备属性报告约 30.00003 fps。
- 连续采集：60.027896 秒。
- 尝试帧数：1793；成功 1793；失败 0；成功率 100%。
- 实测处理循环帧率：29.869446 fps。
- 最大成功帧间隔：0.069013 秒。
- 所有帧形状均为 `1080x1920x3`。
- 重新打开：3/3 次打开和首帧读取成功。
- 正式测试所有判定项均为 `true`。

补充模式预探测：1280×720@30 和 1920×1080@30 均可成功请求；请求 3840×2160@30 时设备回退为 1920×1080，因此本轮不声称 4K Webcam 采集能力。
