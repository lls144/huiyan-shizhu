## 真机 PLC 观测（重要）

| 时间 | 操作 | 结果 |
|---|---|---|
| 09:12 | `m8_real_plc_acceptance.py --check-access --db-number 3` | **PASS**：`magic=0x4D38`、`version=1`、`AcceptanceReady=TRUE`、`CycleCounter` 递增、队列空、灯全灭 |
| 09:15–09:16 | 合成自检（默认参数曾连真机）13 次命令写入 | 全部报 `S7ProtocolError class=0x81 code=0x04`，**0 条进入队列** |
| 09:16 | `--diagnose` | `connect_ok=true`，但 `db_read_ok=false`，hint 指向 PUT/GET 未开放 |
| 09:20 | `--check-access` 连续 3 次重试 | 稳定失败，同一错误码 |

结论：PLC 可连上，但 CPU 当前不向远程伙伴提供 DB 读/写服务。按工具提示，需要在 TIA 打开
`Protection & Security → Connection mechanisms → Permit access with PUT/GET communication from remote partner`
并重新下载；在此之前 M7/真机闭环无法进行。

诚实说明：本次的 13 次写入全部失败，因此 **实验室 PLC 的 FIFO 没有被本程序改动**；
但这也意味着“传送带 → 真机 PLC”这条链路今天没有取得任何真机证据。

## 顺带修正的两个设计问题

1. 合成/离线运行默认**不连 PLC**（只有显式给 `--plc-config` 才打开命令桥），
   避免离线自检误写实验室设备。真实演示仍按 `--plc-config pc/config/plc.json` 显式开启。
2. 会话 JSON 增加 `plc_dispatch_count` / `plc_sent_count` / `plc_error_count`，
   不再用“命令数”笼统代表“写入成功数”。
