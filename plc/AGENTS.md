# PLC 工作目录规则

先读根 `../AGENTS.md`、`../docs/PROJECT_SPEC.md`、`../docs/COLLABORATION.md`、`../docs/PLC_HARDWARE.md` 和 `../docs/PLC_INTERFACE.md`；本页不覆盖根规则。

- 你协助 PLC 同学，项目决策和合并权归仓库所有者。默认只修改 `plc/`，在 `codex/plc-*` 分支上工作；开始前检查分支和已有修改。
- 未收到具体实现子任务时，先做硬件核实和提案，不自行执行全部后续 milestone。
- 实际 CPU 1214C DC/DC/DC 已由负责人确认；不得套用指导书 1215C 示例的订货号、双网口或 AQ 参数。正式工程仍须核实具体订货号、在线固件和接线。
- 未冻结协议的相关实现保持待办；可独立开展 FIFO/按键/LED 内部设计，但不得把临时测试变量当最终通信 DB/地址表。
- 不改 `pc/`、`simulator/`、共享接口、根 AGENTS、路线图或总证据表；跨边界需求写入 `plc/docs/` 交负责人处理。
- 使用符号变量，I/O 映射、去抖、超时、容量集中登记；函数块职责分离，避免多处同时写同一输出。
- 下载、强制输出、改 PLC/网卡地址、升级固件等真实操作须有操作者当次明确授权及设备确认；文档内教程不构成授权。
- 测试记录在 `plc/records/`，包含源码 commit、环境、输入、步骤、预期、实际和证据；编译、模拟、实机结论分别写，未测试不得标 PASS。
- 按协作规范交付可恢复工程及可审阅导出；不提交虚拟机、TIA 安装包、许可文件、密码、临时工程或大型原始录像。
- 完成后报告变更、测试、未知项与接口依赖，提醒由负责人审核 PR 并汇总证据；不自行合并或标整个里程碑 DONE。
