# “慧眼识珠”——AI 视觉仓库物流模拟系统 综合实验报告

课程项目 · 自动化专业综合实验

## 摘要

本系统以笔记本电脑与实验室 PLC 实验箱为核心硬件平台，构建“视觉识别 → 队列缓存 → 按键出队 → LED 分拣”的完整闭环：PC 端用 Python + OpenCV 完成图像预处理、轮廓特征提取与基于 `approxPolyDP` 的三类形状分类；识别结果经事件去重后通过 S7 通信写入 PLC 的 FIFO 队列；操作者按实验箱出队键逐条出队；PLC 按形状点亮 1/2/3 盏 LED 模拟分拣。系统另提供三节传送带可视化程序，把“三角形走第一段、矩形走第二段、圆形走第三段”的分拣规则以动画呈现，便于演示。

全部结论均来自真实设备测试：相机实测 30 fps；三类形状实时识别全部正确；真机 PLC 自动验收 12/12 通过；视觉到实体灯的完整闭环多次跑通；断电重启、拔网线断连、按键出队等边界行为均有实测记录。未完成或不成立的项在文中明确标注，不以模拟结果替代真实证据。

## 3 视觉识别方案（实现级）

本章描述的是仓库中**实际运行的代码路径**，对应文件 `pc/vision/preprocess.py`、`contours.py`、`classifier.py`、`pipeline.py`、`roi.py`。

### 3.1 预处理链

对每一帧执行以下步骤（全部参数来自 `vision.json`）：

| 步骤 | 实现 | 参数 |
|---|---|---|
| ① ROI 裁剪 | 先按归一化 ROI 裁出工作区 | 配置 `roi_left/top/right/bottom`＝`0.24/0.08/0.76/0.75`；运行时校准可覆盖 |
| ② 灰度化 | `cv2.cvtColor(BGR2GRAY)` | — |
| ③ 灰度归一化（可选） | CLAHE | `clipLimit=2.0`，`tileGridSize=8×8`；**仅对照方案**使用 |
| ④ 平滑 | `cv2.GaussianBlur` | 核 `5×5` |
| ⑤ 二值化 | `cv2.threshold(THRESH_BINARY_INV | THRESH_OTSU)` | **反相**，因为目标是深色物体、背景为白色 |
| ⑥ 形态学开运算 | `cv2.morphologyEx(MORPH_OPEN, 椭圆核)` | 核 `3×3`，1 次 |
| ⑦ 边缘（诊断用） | `cv2.Canny` | 低 50 / 高 150 |

第 ⑦ 步的 Canny 图**不参与分类**，只作为证据链中的诊断图保存，便于定位“二值化切得不好”与“轮廓筛选过严”这两类问题。

### 3.2 轮廓特征提取

对二值图做 `findContours(RETR_EXTERNAL, CHAIN_APPROX_SIMPLE)`，对每个外轮廓计算以下**可解释特征**：

| 特征 | 计算方式 |
|---|---|
| `area` / `area_ratio` | `cv2.contourArea`；面积比 = 面积 ÷ ROI 面积 |
| `perimeter` | `cv2.arcLength(closed=True)` |
| `vertices` | `cv2.approxPolyDP(contour, ε = 0.02 × 周长, closed=True)` 的顶点数 |
| `solidity` | 面积 ÷ 凸包面积（`cv2.convexHull`） |
| `circularity` | `4π·面积 ÷ 周长²`，圆为 1 |
| `aspect_ratio` | `min(w,h) ÷ max(w,h)`，由 `cv2.boundingRect` 得到 |
| `min_rect_fill_ratio` | 面积 ÷ 最小外接矩形面积（`cv2.minAreaRect`） |
| `max_right_angle_deviation_degrees` | 仅当逼近结果为 4 点时计算四个内角与 90° 的最大偏差 |
| `is_convex` | `cv2.isContourConvex` |
| `touches_border` | 外接矩形是否距 ROI 边界 ≤ 2 px |

### 3.3 轮廓筛选规则

每个候选轮廓都会被记录**是否通过**以及**未通过的原因字符串**（这是报告里“为什么这个物体没被识别出来”的取证依据）：

| 拒绝原因 | 条件 |
|---|---|
| `area_ratio_below_minimum` | 面积比 < 0.02 |
| `area_ratio_above_maximum` | 面积比 > 0.25 |
| `solidity_below_minimum` | 实心度 < 0.90 |
| `touches_roi_border` | 触碰 ROI 边界（2 px 内） |

通过全部四条即视为有效目标。**“触边即弃”是有意设计**：横跨 ROI 边界的大块区域通常是人体、桌面边缘等背景，放进来会造成误检；代价是取景时目标必须完整落在框内——这一点在 M3 复测中被真实踩到（见 §10）。

### 3.4 形状判定规则

按顺序匹配，命中即返回：

| 形状 | 判定条件 | 拓扑分 | 几何分 |
|---|---|---|---|
| **三角形** | 凸 && 顶点数 = 3 | 1.0 | `lower_is_better(圆度, 阈值 0.72, 优 0.62)` |
| **矩形** | 凸 && 顶点数 = 4 && 最大直角偏差 ≤ 25° && 最小外接矩形填充比 ≥ 0.8 | 1.0 | `(角度分 + 填充分)/2`，角度优 ≤5°、填充优 ≥0.95 |
| **圆形** | 凸 && 顶点数 ≥ 6 && 圆度 ≥ 0.78 && 长宽比 ≥ 0.8 | `higher_is_better(顶点数, 6, 8)` | `(圆度分 + 长宽比分)/2`，圆度优 ≥0.92、长宽比优 ≥0.95 |
| 以上都不满足 | — | — | 输出 `unknown`，置信度 0 |

三角形用**圆度低**作为几何证据：三角形越“尖”，圆度越接近 0.5–0.6；四边形若被压成接近正方形则圆度升高，由此与三角形区分。

### 3.5 置信度的定义（不是概率）

```text
confidence = 0.5 × 拓扑分 + 0.3 × 几何分 + 0.2 × 质量分
质量分     = (实心度分 + 面积余量分) / 2
```

- **拓扑分**：顶点数等“结构性”证据的符合度；
- **几何分**：各形状特有的几何指标（直角偏差、圆度、长宽比、填充比）的符合度；
- **质量分**：实心度（阈值 0.90 → 优 0.98）与“面积既不太小也不太大”的余量（余量比 0.03 为满分）。

分数映射统一使用两段线性函数 `_higher_is_better` / `_lower_is_better`：等于阈值得 0，达到“优”值得 1，中间线性插值。**该值只表示几何规则的符合程度，不是统计概率**，这一点在 `notes/decisions/DECISION-001` 中明确定义，报告中不得按概率解读。

### 3.6 ROI 校准策略

采用“启动校准 → 运行锁定”，不逐帧追踪，避免面积与置信度抖动。校准顺序为 **自动 → 手动 → 配置固定值**：

1. **自动检测**：HSV 过滤白纸（`V ≥ 140`、`S ≤ 100`）→ 形态学闭/开 → 取面积比在 `0.12–0.85` 的候选四边形；
   打分 = `0.2×面积分 + 0.3×矩形度 + 0.25×居中分 + 0.25×亮度分`，
   其中矩形度要求 ≥0.7、居中分按中心距 ≤0.5 衰减、亮度分要求亮像素占比 ≥0.6；
   **总分低于 0.45 即判失败**，进入手动。
2. **手动框选**：操作者在预览窗口拖框，最小 80×80 像素。
3. **配置固定值**：以上都失败时用 `vision.json` 的归一化 ROI。

校准确认后写入运行时文件（`output/m2/runtime-calibration.json`，Git 忽略），后续可加 `--reuse-calibration` 复用。之所以**不**把新机位 ROI 直接写进 shipped 配置：该配置同时是合成夹具与 M3 数据集的隐含输入，直接改会让 8 个既有测试失败（ISSUE-003）。

### 3.7 显示稳定滤波

预览窗口另加一个**只影响显示**的多数表决：窗口 5 帧、至少 3 票才切换显示标签，且平票时取更近的一票。逐帧的原始判定与置信度不受影响，仍原样写入证据文件——避免“看着稳”掩盖真实抖动。

### 3.8 多目标（VISION-003）

`analyze_multiple_objects` 保留**所有通过筛选的轮廓**，逐个输出标签、置信度、边界框与几何特征；`analyze_image` 则只取面积最大的一个（单目标模式）。二者共用同一套预处理与分类代码，因此单目标与多目标不会出现两套阈值。

### 3.9 实测数据（现用内置 HD Webcam）

**单目标（M2，TEST-017）**：302 s 会话、9036 帧、实测 **30.01 FPS**、0 读失败；空背景 4 次全部无目标；三类各一次全部正确，**未修改任何阈值**：

| 输入 | 判定 | 置信度 | 顶点 | 面积比 | 实心度 | 圆度 | Otsu |
|---|---|---|---:|---:|---:|---:|---:|
| 背景 | no_object | 0.000 | — | — | — | — | 98–146 |
| 三角形 | triangle | 1.000 | 3 | 0.1353 | 0.9846 | 0.5540 | 90 |
| 矩形 | rectangle | 0.984 | 4 | 0.1712 | 0.9803 | 0.7225 | 84 |
| 圆形 | circle | 0.980 | 8 | 0.1910 | 0.9962 | 0.9010 | 115 |

用 §3.4/§3.5 的规则复核这三个样本：三角形 3 顶点、圆度 0.554 < 0.62 → 几何分满分；矩形直角偏差与填充比均达到“优”；圆形 8 顶点、圆度 0.901、长宽比接近 1 → 三项高分。实测置信度与规则推演一致。

**多目标与光照（M3，TEST-018）**：同屏三目标、两种预处理对照：

| 工况 | 亮度均值 | otsu | clahe+otsu |
|---|---:|---|---|
| 正常光照 | 114.5 | 3 个：triangle 0.992 / rectangle 0.953 / circle 0.921 | 完全一致 |
| 侧光 | 123.2 | 3 个：triangle 0.959 / rectangle 0.946 / circle 0.970 | 完全一致 |

## 4 事件去重与生产者-消费者前置（M4）

逐帧检测会连续多帧命中同一物体，直接入队会造成重复。`ObjectStateManager` 的做法：

1. **关联**：同标签且（IoU ≥ 0.30 或中心距 ≤ 80 px）才认为是同一物体；候选对按 IoU 降序、中心距升序贪心配对，保证一个检测框只匹配一个轨迹。
2. **确认**：连续命中 ≥ 2 帧才确认为真实目标并产生 **ENTER**；
3. **保持**：短暂丢失 ≤ 3 帧仍保持同一 ID（用于抗抖动与短暂遮挡）；
4. **退出**：连续丢失 > 3 帧判定离开，产生 **EXIT**；再次进入分配新的 object ID。

事件模型是“每个物体至多一次 ENTER、至多一次 EXIT”，与“识别一次只入队一次”的任务要求直接对应。

**真机实测（TEST-019）**：3965 帧会话产生 **66 个事件 = 33 ENTER / 33 EXIT 完全配对**，33 个目标**没有任何一个产生重复 ENTER**，事件 ID 1→66 连续；另一轮 75 秒短跑产生 29 个事件（16 ENTER / 13 EXIT，结束时仍有 3 个目标在场故其 EXIT 未产生，符合设计）。离线另有 12 个确定性 detection 序列场景覆盖停留、短暂丢失、离场重入与并发多目标（TEST-005）。

> 边界：M4 完成只代表 **PC 端事件生成子能力**，不代表 PLC-002 整体、真实 FIFO 或通信完成。

## 5 PC–PLC 通信（M7 / COMM）

### 5.1 为什么选 S7 over Ethernet

任务书正文允许“串口/以太网”，硬件方案表写“网线”；现场只确认了以太网口与 S7 能力。自定义帧需要 PLC 侧另写接收解析逻辑，课程时限内没有收益，因此采用 PC 主动连接 PLC、以 `DB_M8_Acceptance` 绝对偏移作为“帧结构”的方案。完整字段表、时序、测试向量见 `docs/PLC_PROTOCOL_M7.md`。

### 5.2 关键工程发现：控制字写会被静默丢弃

真机联调初期 `--all` 验收随机失败，失败点每次不同。逐项排除后定位到：**该 CPU 对 `DBB0–DBB7` 的 PUT/GET 写约一半会被静默丢弃**（对照实验：写 `M` 区 10/10 成功，写该 DB 5/10 成功），而 `db_write` 返回成功并不代表 PLC 收到了数据。

对策：**每次写都读回校验，不一致就重发**，直到 PLC 真的持有该值。加入后 `--all` 连续四轮 **12/12 全绿**：193 次确认写中有 90 次需要重发、单笔最多 5 次（上限 12 次）。该机制是幂等的——被丢弃的那次写从未在 PLC 侧产生 `CommandValid` 上升沿。

### 5.3 可靠性层

| 机制 | 实现 |
|---|---|
| 确认（ACK 等效） | 写前读队列长度，写后必须 +1；`auto_dequeue` 或人工按键时以“刚出队的语义号 == 本命令语义号”确认 |
| 重复保护 | 已确认过的语义号**永不第二次写入**，从机制上杜绝“重发导致重复入队” |
| 队列满通知 | 写前读 `QueueFull`，满则不写并报 `QUEUE_FULL`，默认**延后补发**（每 0.5 s 尝试） |
| 超时/未确认 | 超时或复读后仍无法确认 → `UNCONFIRMED`，界面显示“待核实”，不伪装成成功 |
| 断线自愈 | snap7 客户端不会自愈、且 `connect` 对无应答对端要阻塞约 10 s；加入 0.5 s TCP 探活 + 短超时 + 限速重连后，断线判定从 15.8 s 缩短到 **2.09 s** |

### 5.4 心跳与断连报警（COMM-002）

PC 每秒把心跳计数写入 `DBB2` 并读回确认；PLC 在 `TestEnable AND HeartbeatEnabled` 时启动 2 s 看门狗，计数器 2 秒无变化即报警，并把报警位镜像到 `DBX8.7` 供 PC 回读。

**真机实测**：心跳周期 **1.00–1.03 s**（均值 1.016 s）；停发心跳后 **2.015 s** PLC 报警位置位；三盏灯以 **2.026 Hz** 同步全闪（2.468 s 内 10 次跳变，亮/灭均观察到）；心跳恢复后报警自动清除。拔网线实测：PC 侧 **2.09 s** 判定中断，插回后自动恢复并记录中断时长 18.109 s。

## 6 PLC 端设计与真机验证

### 6.1 结构

| 块 | 职责 |
|---|---|
| `FB_Fifo` | 容量 3 的环形 FIFO，给出空/满/长度 |
| `FB_ButtonPulse` | 2 个扫描周期的去抖与上升沿，保证“按一次只出队一条” |
| `FB_LedDisplay` | 按形状编码锁存 1/2/3 盏；预留断连全闪接口 |
| `FB_PlcApplication` | 组合 FIFO/按键/灯，输出最近出队形状与语义号 |
| `FB_M8_AcceptanceHarness` | 联调包装：DB 命令与真实按键合流，供 PC 自动验收；含 COMM-002 看门狗与全闪 |
| `DB_M8_Acceptance` | PC 读写用的 24 字节非优化 DB（当前 DB3） |

### 6.2 行为语义（真机确认）

- **入队不亮灯**：识别入队后灯保持上一次出队的结果；
- **出队才亮灯**：按一次出队键出队一条并锁存 1/2/3 盏；
- **复位**：清空队列、灯全灭、`last_dequeued` 清零；
- **断电重启**：队列、灯、`last_dequeued` 全部清空。

真机数据（TEST-013）：一次入队三条（队列满 3），操作者按三次出队键，依次得到
`queue 2 / leds [1,0,0] / shape 1` → `queue 1 / leds [1,1,0] / shape 2` → `queue 0 / leds [1,1,1] / shape 3`，现场照片与之一致（`evidence/screenshots/m8-real/`）。自动验收 `--all` 连续 **12/12 AUTO PASS**。

## 7 上位机与分拣可视化

### 7.1 M5 上位机

PySide6 6.11.2；采集与视觉运行在 `QThread` worker，UI 只消费容量 1 的 latest-frame-wins 快照，界面卡顿不会拖慢识别。真机 600 秒长跑（TEST-019）：17549 帧、**处理与界面更新同为 29.234 FPS**、0 读失败、0 丢帧、0 缓冲覆盖、正常停止；另一轮 75 秒带三类目标的运行中 `detection_count=3720`、事件 29 条，截图显示画面、类别、置信度、目标状态与事件在同一界面同步刷新。

### 7.2 三节传送带分拣可视化

`pc/sorting/`：识别到的物体以物料块进入**可视化缓冲区**，随后走上三节串联传送带——第 1 段代表三角形、第 2 段矩形、第 3 段圆形；物料块在**自己那一段**被推出并示意，否则继续进入下一段；离开的同时把形状编码写入 PLC。

必须说明的边界：传送带**不做第二次识别**，物料块携带的标签就是视觉已给出的结果，三段带子只是把分拣去向可视化。与 PLC 的连接时点可配置（`plc_trigger`：`exit` 默认 / `enter`），两者的形状编码与灯数完全一致。

## 10 问题分析与局限

### 10.1 已解决的问题（均有记录与证据）

| 问题 | 根因 | 处置 |
|---|---|---|
| 真机验收随机失败 | PUT/GET 写该 DB 约一半被静默丢弃 | 写→读回→重发（幂等） |
| ISSUE-002 固件登记冲突 V4.1 vs V4.5.1 | 两处来源不同、截图未归档 | 双来源互证后统一为 **V4.5.1** 并结案 |
| ISSUE-003 视觉配置 ROI 与合成夹具耦合 | ROI 同时是数据集隐含输入 | 改用运行时校准文件，不动 shipped 配置 |
| ISSUE-004 TIA 工程 31 个编译错误 | 外部源是**工程内副本**，磁盘改了工程没更新；调用点接口过期 | 重加源 → 按序生成 → 更新调用点 |
| 插回网线后链路不恢复 | snap7 客户端不自愈，且 connect 阻塞约 10 s | 0.5 s TCP 探活 + 短超时 + 限速重连 |
| 报警位对但灯不闪 | 直接读定时器实例成员 `#BlinkTimer.Q` 在同一次扫描取到旧值 | 改用显式输出 `Q => #BlinkPulseState` |

### 10.2 现存局限（如实列出）

1. **相机与取景方式**：现用内置 HD Webcam 固定在屏幕上方，**无法三脚架垂直俯拍**，采集必须手持 A3 白纸对准镜头，构图一致性依赖操作者。
2. **自动曝光吃掉“较暗”工况**：三次尝试变暗，实测亮度均未低于正常组（122.4 / 116.2 / 114.1 vs 114.5），说明摄像头在自动补偿增益。要复现受控暗光必须先锁定曝光。
3. **触边目标被排除**：`touches_roi_border` 会丢弃跨边界目标（设计如此），对取景提出要求——M3 复测中曾因此只识别到 2/3 个目标。
4. **遮挡与粘连**：`RETR_EXTERNAL` 外轮廓在矩形与圆形接触时输出合并轮廓（`unknown`），属算法固有局限。
5. **PLC 侧无序列号去重**：目前靠 PC 端“已确认语义号不重发”保证不重复入队；真正的“超时重发 + PLC 去重”需增加序列号字段。
6. **通信为单生产者假设**：多 PC 并发未定义。
7. **验证覆盖**：系统级多工况矩阵与演示视频尚未完成；多目标连续场景的真实运行轮次偏少；`DB_M8_Acceptance` 与 TIA 工程组态的固件号是否统一仍待操作者确认。

## 11 改进方向

1. **增加颜色维度**：在几何分类之外加入 HSV 色调判据，区分同形状不同颜色物料（任务书明确提到的改进方向）。
2. **引入优先级队列**：把 FIFO 扩展为按优先级出队，适配“紧急订单插队”。
3. **换外接摄像头 + 三脚架俯拍**：回到任务书原始硬件方案，解决取景一致性与曝光控制。
4. **锁定相机曝光**：取得真正可复现的暗光工况，补齐 VISION-004 的第三种条件。
5. **协议补齐序列号与 ACK 字段**：实现确认超时后的受控重发且 PLC 侧去重。
6. **报警独立指示**：把断连报警做成业务灯之外的独立指示，避免与分拣结果显示互相干扰。

## 12 结论

本系统完成了任务书要求的核心闭环：真实摄像头识别三类形状、识别结果经去重后进入 PLC FIFO、按键逐条出队、按形状点亮 1/2/3 盏 LED 模拟分拣，并额外提供了三节传送带可视化演示。系统在真机上完成了自动验收 12/12、视觉到实体灯闭环、断电重启、按键出队、拔网线断连与恢复、心跳中断报警与全闪等验证，所有结论均可追溯到 `notes/tests/` 的测试记录与 `evidence/` 的截图与数据。

同时，本报告如实记录了三类未完成或不成立的内容：内置摄像头下“较暗”工况无法复现、遮挡/粘连为算法固有局限、M7 协议尚未定版（因此 M9 里程碑仍为 TODO）。这些局限连同改进方向一并列出，不以推测代替证据。
